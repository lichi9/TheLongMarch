## 为什么文件夹名是人名，不是关卡号

这是整个架构里最重要的一条。

如果文件夹叫 `level07`，所有人都会默认它是「第 7 关」。等你后期要调整顺序，
要么改文件夹名（21 个路径全变，所有人的分支全部冲突），要么把「7 号同学」硬塞到第 3 位，
读代码的人永远在脑内做一次翻译。

所以：

- **文件夹名 = 人的缩写**，只表示「这一格归谁」
- **剧情顺序 = `core/route.js` 里的数组顺序**，只表示「先玩哪关」

两者之间没有耦合。调顺序就是在 `route.js` 里挪一行，21 个人的文件夹一个字都不用改。
存档也绑 `id` 不绑序号，所以调多少次顺序，进度都不会错乱。

成员不需要知道自己是第几关——他只需要知道自己写的那一关叫什么事件。

## 三条边界

**一、只写自己的格子。**
`levels/你的缩写/` 之外的东西，包括 `index.html`、`core/`、根 `assets/`、`docs/`、
别人的关卡，一律只读。

**二、草稿不进库，成品必须进库。**
`_draft/` 随便扔，它已经被忽略；`assets/` 里放别人 clone 下来必须有的东西，必须提交。

**三、只推自己的分支，合并交给部长。**
分支名和文件夹名一样，就是你的缩写。写完 push 上去，在 Gitee 上提 PR 到 `develop`。

---

## 分支

| 分支 | 谁写 | 说明 |
| --- | --- | --- |
| `master` | 只有部长 | 随时能展演的稳定版，每次合并打 tag |
| `develop` | 只能通过 PR 合入 | 日常集成分支，允许半成品 |
| `<你的缩写>` | 你自己 | 想怎么提交都行，坏了只影响自己 |

21 条个人分支并行，互不干扰。

---

## 命名约定

- 文件夹、文件名：**全小写 ASCII**，多个词用连字符（`ice-climb.js`）
- 不改文件夹名，不改文件名的大小写（Windows 不区分，改了 git 认不出）
- 关卡 `id` 一旦定了就不再改，它是存档的键
